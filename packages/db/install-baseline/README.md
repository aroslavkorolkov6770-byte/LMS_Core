# Полная схема новой установки

`0000_core_runtime_v1.sql` — отдельная baseline для пустой PostgreSQL, а не очередная миграция существующей базы. Она содержит 22 актуальные таблицы, ограничения и индексы. Данные пилотных клиентов/пользователей в SQL не включаются.

Генерация: из папки `packages/db` выполнить script `db:generate:fresh`. Сначала компилируется TypeScript, затем Drizzle читает только `dist/src/schema/index.js`. Это важно: рядом с исходными TS существуют старые JS, подхватывать их при генерации нельзя. Они не удалялись.

Историческая папка `drizzle` и ее журнал не изменялись. Первый ошибочный черновик `fresh-install` не используется и не включается в backend-архив.

`baseline-spec.json` фиксирует версию, SHA256 SQL и описание скомпилированной схемы. Упаковщик не подставляет новый hash схемы в старый SQL автоматически: несовпадение останавливает упаковку. LF для SQL закреплен в корневом `.gitattributes`.

Применение выполняет `initializeFreshDatabase`: проверяет hash SQL и описание схемы, берет транзакционную блокировку, отказывается от чужой непустой базы, создает таблицы/одного клиента/стандартные определения ролей и installation marker одной транзакцией. Пользовательские аккаунты создаются позже приватным bootstrap. При повторе для той же установки ничего не заменяет; изменение клиента, исходной конфигурации, версии/SQL или структуры блокируется.

Не запускать SQL вручную на рабочей `lms_core`. Изменение будущей baseline требует новых тестов на пустой БД и отдельного пути обновления уже установленных версий; автоматический upgrade существующей схемы здесь не реализован.
