# LMS Core

Исходный код LMS-ядра и локального Windows-приложения для подготовки и управления отдельными LMS клиентов. Снимок исходников от 2 ноября 2026 года.

## Состав

| Каталог | Назначение |
| --- | --- |
| `apps/control-center` | Electron-приложение: сервисы, Git-источники, установка и обслуживание клиентов |
| `apps/deploy-panel` | Next.js-панель клиентов |
| `apps/api` | NestJS API |
| `apps/lms-web` | Локальная веб-часть и API оформления |
| `packages/db` | PostgreSQL, Drizzle, схемы и миграции |
| `packages/shared` | Общие типы и контракты |
| `packages/config` | Общая конфигурация |
| `infra/scripts` | Запуск, установка, обновление и обслуживание |
| `infra/desktop` | Сборка Windows-дистрибутива |
| `infra/testing` | Проверки и изолированные приемочные сценарии |

## Работа с исходниками

Нужны Node.js, Git и pnpm. В `package.json` указан pnpm 9.12.3. Для рабочего локального окружения также требуется PostgreSQL; команды настройки находятся в `infra/scripts`, описание — в `infra/local-postgres-setup.md`.

Из корня репозитория:

```powershell
pnpm install --frozen-lockfile
pnpm build:shared
pnpm build:db
pnpm check
```

После настройки собственного окружения приложение запускается командой:

```powershell
pnpm dev:control-center
```

Это исходники, а не готовый установленный экземпляр. Зависимости, настройки PostgreSQL и собственные секреты необходимо подготовить отдельно. Примеры конфигурации: `infra/.env.example` и `apps/control-center/config/launcher-secrets.example.json`. Значения из примеров не являются production-доступами.

## Проверки и состояние

Перед этой публикацией `pnpm check` успешно выполнен в исходной рабочей копии. Полная новая установка на чистом компьютере в рамках публикации не проверялась. Текущие ограничения перечислены в `TASKS.md`.

В репозиторий входят исходники, тесты, миграции, ресурсы интерфейса, lock-файл и скрипты сборки установщика. Локальные базы, `.env` с доступами, настройки клиентов, runtime-кэши, резервные копии, журналы, `node_modules`, собранные EXE и отдельные исторические скрипты для конкретных серверов не публикуются. Частные отчеты и история эксплуатации остаются в локальном проекте.

Каждый клиент использует отдельный хост и отдельную базу. Публикация исходников не означает завершение production-приемки.
