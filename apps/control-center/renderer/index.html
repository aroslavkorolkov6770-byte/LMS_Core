    Доступы и запуск

    Перед изменением сервера Core покажет отдельное окно подтверждения.

    PostgreSQL и администраторы LMS

    Core создаст отдельную базу и служебный пароль. Для PostgreSQL на этом же подготовленном сервере пароль postgres не нужен.

    Доступы подставляются из карточки выбранного клиента.

    Завершите подготовку перед установкой.

    Открыть установленную LMS

    SSH-просмотр работает без публичного порта. Доступ по IP настраивается отдельно.

    Открытие станет доступно после успешной установки выбранного клиента.

    ИИ: Alice AI

    Все параметры ИИ — здесь. Core запишет их в серверный .env.production.local и перезапустит только веб-службу этой LMS.

    Токен еще не проверен.

    Укажите ID каталога и совместимого Prompt клиента. «Создать базу и подключить» создаст отдельный пустой Vector Store или использует ранее созданный Core для этого клиента и сам запишет его ID. Поле Vector Store для этой команды заполнять не нужно. Создание самого Prompt через API Яндекс не поддерживает: один раз сохраните конфигурацию в Responses API, не текстовый runtime-agent. Номер клиента, название и ID API-ключа не заменяют эти ID.

    Проверка читает наличие параметров и состояние LMS, но не вызывает платный ИИ и не проверяет действительность токена.

    Почта уведомлений и поддержки

    Один адрес для отправки уведомлений, футера, mailto-ссылок и контактов в политике. Core применит его на сервере; адреса сотрудников не меняются.

    Пароль не сохраняется на ноутбуке.

    В исходной LMS STARTTLS включается, когда SMTP-сервер предлагает его; без такого предложения обработчик может допустить незашифрованное соединение. Для уведомлений используйте TLS-порт, если провайдер его поддерживает. Тестовое письмо Core требует TLS в обоих режимах.

    Первая настройка старой LMS может потребовать отдельной сборки адаптера; до переключения старый сайт работает. Последующие смены почты — без сборки. Чтение настроек не отправляет писем; тест подтверждается отдельно. Правила уведомлений и адреса сотрудников остаются прежними.

    Доступ в обычном браузере

    Сначала настройте доступ по IP, затем включите HTTPS. Сертификат и автопродление настраиваются на сервере; ноутбук можно выключать. Нужны открытые порты 80 и 443. До HTTPS используйте только временные учетки и ненастоящие данные.

    Выпуск потребует отдельного подтверждения условий Let's Encrypt и публикации IP в журналах сертификатов. Приватный ключ остается на сервере.

    Полное удаление LMS и БД

    После проверенной резервной копии удаляются сайт, его отдельная БД, SQL-роль и служебная Linux-учетка. Карточка клиента и сохранённые доступы остаются для новой установки. Другие сайты и общий PostgreSQL/Nginx не затрагиваются.
